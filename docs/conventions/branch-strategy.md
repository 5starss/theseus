# 🌿 Branch Strategy & Convention

테세우스 프로젝트의 브랜치 전략 및 협업 컨벤션을 정의합니다.
모든 팀원은 아래 규칙을 준수하여 일관된 협업 환경을 유지합니다.

---

## 🔀 Merge Request (MR) 제목 규칙

```
JIRA번호 [label]: 작업 내용
```

### 📌 예시

```
S14P11A503-123 [feat]: 회원가입 API 구현
S14P11A503-123 [fix]: 홈 화면 네브바 수정
```

### 🏷️ Label 종류

* `feat` : 기능 추가
* `fix` : 버그 수정
* `chore` : 기타 작업 (설정, 의존성 등)
* `refactor` : 리팩토링
* `docs` : 문서 수정
* `test` : 테스트 코드

---

## 🌱 브랜치명 규칙

```
label/JIRA번호/기능요약
```

### 📌 예시

```
feat/S14P21A503-123/initial-user-info
```

### 📌 작성 기준

* `label` : 작업 유형 (feat, fix 등)
* `JIRA번호` : 작업 티켓 번호
* `기능요약` : 영어 소문자 + kebab-case

---

## 💬 커밋 메시지 규칙

```
JIRA번호 [label]: 작업 내용
```

### 📌 예시

```
S14P11A503-123 [chore]: 스프링 부트 프로젝트 초기 세팅
```

---

## 📌 이슈 관리 방식

* GitLab에서는 별도의 Issue를 생성하지 않습니다.
* 모든 작업 내용은 **JIRA 스토리의 설명란**에 작성합니다.

---

## 🎯 목적

* 작업 이력의 명확한 추적
* JIRA와의 연동을 통한 효율적인 협업
* 일관된 코드 관리 및 리뷰 환경 구축
