# Theseus 제품 비전

> 작성일: 2026-05-08

---

## 한 줄 정의

> **"전문가 없이 내 환경에 맞는 에이전트를 직접 만든다"**

---

## 핵심 문제 인식

### 현재 AI 에이전트 도구의 한계

```
Claude Code / Cursor / Copilot
    ├── 범용 코딩 에이전트 → 특정 환경 최적화 불가
    ├── 복잡한 작업 = 긴 프롬프트 = 높은 토큰 비용
    ├── 커스터마이징 없음 (MCP 제외)
    ├── 클라우드 의존 → 보안 민감 환경 사용 불가
    └── 에이전트 전문 지식 없으면 제대로 활용 어려움
```

### Theseus가 해결하는 것

```
1. 에이전트를 모르는 개발자도 create_tool로 즉시 시작
2. 복잡한 작업을 툴로 캡슐화 → 토큰 비용 구조적 절감
3. 완전 로컬 실행 → 보안 민감 환경에서도 운용 가능
4. 하네스 엔지니어링 플랫폼 → 내 환경에 맞는 에이전트 설계
```

## 타겟 사용자

### 타겟 1 — 에이전트 초보 개발자

```
상황: 코드는 잘 쓰지만 AI 에이전트를 어떻게 활용할지 모름
페인포인트: 기존 도구는 "잘 쓰려면 프롬프트 엔지니어링을 배워야 함"
해결: create_tool로 익숙한 Python 코드를 작성하면
      에이전트가 즉시 그 툴을 사용
성장 경로: 툴 하나 → 툴 묶음 → 팀 하네스 설계자
```

### 타겟 2 — 효율을 원하는 개발팀

```
상황: 반복적인 모니터링, 배포, 검증 작업을 에이전트로 자동화하고 싶음
페인포인트: 복잡한 작업일수록 프롬프트가 길어지고 토큰 비용이 폭증
해결: 복잡한 로직을 툴로 캡슐화
      → 에이전트는 툴 이름만 호출 (토큰 최소화)
      → 실제 실행은 로컬 Python 코드

예시:
  프롬프트 방식: "서버 A, B, C의 CPU/메모리를 확인하고 임계치 초과 시..." (2000토큰)
  툴 방식:       check_infra_health(servers=["A","B","C"])                  (50토큰)
```

### 타겟 3 — 보안이 중요한 시설

```
상황: 병원, 군사시설, 금융기관, 공공기관
페인포인트:
    - 클라우드 AI 도구 사용 불가 (데이터 외부 전송 금지)
    - AI 에이전트 전문가 고용 어렵고 비쌈
    - 내부 시스템 연동 특화 에이전트가 필요함

해결:
    standalone 모드  → 완전 로컬 실행, 인터넷 불필요
    로컬 LLM 연결   → 데이터 외부 유출 없음
    create_tool     → 내부 시스템 연동 툴을 직접 제작
    RBAC            → 기관 보안 정책에 맞는 권한 통제
    PLAN 모드       → 자동화 전 검토 단계로 안전성 확보
```

## 핵심 가치 — 하네스 엔지니어링

```
일반 에이전트: LLM + 고정된 기본 툴셋
               → 범용이지만 내 환경에 맞지 않음

Theseus: LLM + 내가 설계한 툴셋 (하네스)
          → 에이전트가 내 환경의 언어로 작동
```

하네스 = 에이전트가 작동하는 틀
- 어떤 툴을 쓸 수 있는지
- 어떤 권한으로 실행하는지
- 어떤 워크플로우로 동작하는지
- 어떤 팀/환경에 특화되어 있는지

**에이전트를 쓰는 도구가 아니라 에이전트를 설계하는 플랫폼.**

## 토큰 효율 구조

```
복잡성을 프롬프트에 담으면          복잡성을 툴에 담으면
─────────────────────────────────────────────────────
매 턴마다 긴 컨텍스트 반복          툴 호출 한 번으로 처리
작업 복잡도에 비례한 비용           툴 호출 비용은 고정
LLM이 로직을 직접 실행              Python 코드가 실행
실수 가능성 높음                    검증된 코드가 실행
```

팀이 자주 쓰는 복잡한 작업을 툴로 만들수록 비용과 안정성이 동시에 개선된다.

## 배포 시나리오

| 시나리오 | 연결 | 대상 |
|---------|------|------|
| **standalone** | 인터넷 없음, 완전 로컬 | 개인 개발자, 보안 시설 |
| **hybrid** | 로컬 실행 + 회사 서버 설정 연동 | 팀 도입 |
| **server** | 서버에서 에이전트 실행 | 웹 기반 엔터프라이즈 |

세 시나리오 모두 동일한 코어(`theseus_engine`)를 사용한다.
URL 하나(`THESEUS_SERVER_URL`)로 standalone ↔ 서버 연동이 전환된다.

## 경쟁 포지션

| | Cursor / Claude Code | MCP 툴 | **Theseus** |
|---|---|---|---|
| 커스텀 툴 제작 | 없음 | 외부 제공 툴 사용 | 직접 제작 + 즉시 연결 |
| 토큰 효율 | 프롬프트 의존 | 동일 | 툴 캡슐화로 구조적 절감 |
| 로컬 실행 | 클라우드 의존 | 부분 | 완전 로컬 가능 |
| 보안 환경 | 사용 불가 | 제한적 | 설계 목표 |
| 진입장벽 | 낮음 | 중간 | **낮음 + 성장 경로 존재** |

## 성장 경로 (사용자 관점)

```
Day 1
    create_tool로 첫 번째 툴 만들기
    에이전트가 내 툴을 쓰는 것을 확인

Week 1
    자주 쓰는 작업 5개를 툴로 만들기
    토큰 비용이 줄어드는 것을 체감

Month 1
    팀의 내부 시스템과 연동하는 툴 하네스 구축
    RBAC으로 팀원별 권한 설정

Month 3+
    회사 서버에 하네스 배포
    새 팀원이 하네스를 그대로 사용
```
